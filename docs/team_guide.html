3. Reader andar se: span kaise nikalta hai

Yeh project ka dil hai aur yeh code humne khud likha hai (dlqa/reader.py). Model har token ke liye do numbers deta hai: start logit (hara) aur end logit (orange). Sabse achha (start, end) pair hi jawaab hai. Pehle token <s> ka score "jawaab nahi hai" ka score hai.

start logitend logitchosen span
Rule: score(span) = start_logit[i] + end_logit[j], sirf j ≥ i, span ≤ 40 tokens, passage ke andar. null = start_logit[0] + end_logit[0]. Null jeeta toh "not found". Upar se confidence < 0.6 ho toh bhi "not found" (evaluation se nikala threshold).

4. Background concepts (viva ke liye)

Transformer aur self-attention (2017, "Attention Is All You Need")

RNN tokens ek-ek karke padhta tha; Transformer saare tokens ek saath dekhta hai. Har token ke teen vectors: Query, Key, Value. Score = softmax(Q·Kᵀ/√d), output = scores × V ka weighted sum. Matlab: har shabd baaki shabdon ko dekh ke apna matlab tay karta hai. 8–12 heads parallel chalte hain; position batane ke liye positional encoding jodte hain.

BERT → RoBERTa

BERT (2018) sirf encoder hai. Pretraining: 15% tokens chhupa ke predict karo (masked language modeling). RoBERTa (2019) wahi architecture, 10× data aur behtar training. Pehle bade data pe pretrain, phir chhote task pe fine-tune.

SQuAD 2.0

Stanford ka dataset: Wikipedia passages pe 100k+ sawaal, jawaab passage ka span. Version 2.0 mein 50k unanswerable sawaal bhi hain, isliye model "nahi pata" bolna seekhta hai. Fine-tuning loss: start index pe cross-entropy + end index pe cross-entropy, average. Metrics: Exact Match aur F1 (token overlap, partial credit).

Embeddings aur cosine similarity

Sentence-BERT tareeke se trained model (BGE-base) har text ko 384 numbers ke vector mein badalta hai; same matlab = paas vectors. Cosine similarity vector ki length ignore karke sirf direction compare karti hai. Normalised vectors ka dot product = cosine, isliye FAISS mein inner product use karte hain.

Dense vs TF-IDF (sidebar ka Advanced option)

TF-IDF keyword matching hai, koi neural network nahi: "warranty" poocho toh jahan "warranty" likha hai wahi chunk. Dense matlab se dhoondhta hai: "smart speakers" poocho toh "Alexa and Google Assistant" wala chunk milta hai, jabki "speaker" shabd document mein hai hi nahi. Option isliye rakha taaki baseline vs deep learning live dikha sakein.

Pehli line: "Web page sirf input-output window hai, 150 lines ka. Project uske peeche teen neural networks ka pipeline hai."

Phir bolo mat, dikhao, is order mein:

  1. How much does the kettle cost? → system mana karta hai. Normal app yeh nahi karta.

7. Sawaal-jawaab bank

Poora document model ko kyun nahi dete?
Transformer ~512 tokens hi le sakta hai, aur har chunk pe reader chalana slow hai. Retriever pehle 5 relevant chunks chunta hai, reader sirf unpe chalta hai. Cost O(top-k), document ki length se independent.
Training kyun nahi ki? Bas library call kiya?
Model pehle hi SQuAD 2.0 ke 180k examples pe fine-tuned hai; wahi data pe dobara train karne se wahi result aata, sirf GPU jalta. Training tab useful hai jab apne domain ke hazaaron Q/A pairs hon, jo nahi hain. Isske bajaye humne alag pretrained readers (roberta-base vs large vs deberta) ko apne test set pe compare kiya. Aur pipeline ka har hissa, span extraction se evaluation tak, humara code hai; weights pretrained hain jaise har industry system mein.
ChatGPT se kya alag hai?
ChatGPT document ke bahar se bhi bol sakta hai aur galat bhi bol sakta hai confidently. Yeh sirf document se bolta hai, evidence dikhata hai, aur nahi pata toh "nahi pata" bolta hai.
Loss function kya thi?
Start position pe cross-entropy + end position pe cross-entropy, dono ka average. Unanswerable examples ke liye dono target token 0 (<s>).
Abstain kaise hota hai?
Null score (token 0 pe start+end logit) vs best span score. Null jeeta toh "not found". Upar se confidence (softmax over span vs null) < 0.6 ho toh bhi "not found".
F1 yahan kya hai?
Predicted span aur gold answer ke tokens ka overlap: precision aur recall ka harmonic mean. Near-miss ko partial credit milta hai. Exact Match strict hai: normalise karke poora match.
Chunk size 180 aur top-k 5 kyun?
Sweep kiya: chunk 100 vs 180, top-k 3 vs 5, null margin 0–3. 180 + top-k 5 pe Recall 1.00 aur best F1 bina abstain tode.
Dense aur TF-IDF ka score same kyun?
Test documents chhote hain (4–5 chunks); top-5 mein saare chunks aa jaate hain, toh retriever matter nahi karta. Top-3 pe fark dikhta hai. Lambe documents pe dense retriever ka fayda hota hai. Yeh humne honestly report kiya hai.
Limitations?
Conversation memory simple hai (sirf previous question). Extractive hai, toh summary-type sawaal span se nahi hote; uske liye generator ka overview hai. Scanned PDFs OCR quality pe depend karte hain. Test set chhota aur self-written hai.
1,000 documents pe scale kaise?
FAISS index mein sab documents ke chunks jaate hain, har chunk ke saath file/page id. Reader ka cost same rehta hai kyunki woh sirf top-k padhta hai.
